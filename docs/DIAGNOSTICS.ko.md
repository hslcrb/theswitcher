# 진행률·오류 진단 개발기

## 실제 진행 상태

배치 시작 시 작업 목록을 고정한다. 파일 입력과 출력 형식 선택을 잠시 잠그고, 여러 워커의 진척을 합산한다. 각 파일의 단계는 읽기 → 폰트 구조 검사 → 필요 시 디코더 로딩과 압축 해제 → 필요 시 인코더 로딩과 변환 → 출력 검증 순으로 바뀐다. WOFF 테이블 처리에는 처리된 테이블 개수와 총 개수를 표시한다. WOFF2 코덱이 내부 비율을 보고하지 않을 때는 **마지막 확인값을 유지**한다. 백분율은 경과 시간 추정치가 아니다.

- 배치 백분율과 실행 중인 파일의 백분율은 모두 소수점 한 자리다. 완료 전 반올림으로 `100.0%`가 나타나지 않으며, 작업 처리 결과가 확정된 뒤에만 100.0%가 된다. 실패 역시 처리된 파일로 세되 성공 수와 별도로 표시한다.
- 진척은 단조 증가하고, 워커가 병렬 실행돼 이벤트가 뒤섞여도 바는 뒤로 가지 않는다. 사용자 취소 후에는 그 시점의 부분 진행률을 보존한다. 새 작업을 시작하거나 목록을 모두 비울 때 0.0%로 초기화한다.
- 접근성을 위해 진행바의 값 문구도 제공한다. 동일 상태를 다시 쓰지 않아 화면 읽기 프로그램에 중복 알림을 보내지 않는다. 브라우저의 동작 줄이기 설정을 존중한다.

## 예외 처리와 데이터 경계

| 분류 | 오류 예 |
|---|---|
| 읽기·입력 | 빈 파일, 읽기 실패, 기기별 입력 제한 |
| 구조·호환성 | 잘린 헤더, 지원하지 않는 컬렉션, 테이블 디렉터리·범위, 서로 다른 윤곽 |
| 압축·메모리 | 선언된 크기 불일치, 확장 제한, 결과 보관 한도 |
| 브라우저·코덱 | 워커 시작 실패, 워커 내부 오류, 메시지 전송 실패, 변환 모듈 로딩, Brotli/압축 코덱의 거절, WOFF 스트림 기능 미지원 |
| 출력·시간 | 출력 구조 검증, 파일별 45초 제한 |

오류는 해당 파일 행에 오류 코드와 로컬 번호를 남긴다. 다른 변환은 작업 예산 안에서 계속한다. 오류 기록은 페이지 메모리에서 최근 48건까지 유지하고, 화면에는 최근 16건을 표시한다. 포맷, 파일 크기, 단계, 선택한 출력, 처리 시간(알 수 있을 때), 기록 시각만 JSON으로 내려받을 수 있다. 파일 이름, 글꼴 내용, 파일 경로, 예외 원문과 스택은 로그에 넣지 않는다. 로그 자동 전송, 서버 저장, 로그인·추적 기능도 없다. 페이지를 닫거나 ‘기록 지우기’를 누르면 기록이 사라진다.

## 검증

- 단위 테스트: 0.0·중간·99.9·100.0 표시, 비정상 숫자, 예외 원문 제거, 기록 상한.
- 실제 Chromium: 모바일/데스크톱의 TTF→WOFF2→TTF, 두 개 워커 병렬 및 종료, 단조 진행률과 단계 문구, 저메모리 입력 차단.
- 잘린 파일과 TTF→CFF 유형 불일치를 따로 재현해 오류 코드가 각각 기록됨을 확인했다. JSON을 실제로 내려받고 이름과 내용이 빠진 것, 기록 지우기가 되는 것까지 확인했다.
