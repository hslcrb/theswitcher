# 초기 구현 개발기

**목표:** Convertio류 범용 변환 서비스 중 폰트 작업부터 대체한다. 배포 플랫폼은 정적 자산 전송만 맡고 변환 운영 서버를 두지 않는다. Cloudflare Pages의 GitHub 네이티브 통합을 사용하며 GitHub Actions를 사용하지 않는다.

## 시행착오와 선택

1. 브라우저 전체를 느리게 하지 않도록, 화면은 이름·헤더만 읽고 원본·압축·결과 검증은 파일마다 수명이 제한된 Web Worker로 격리했다. 폰트마다 작업자를 새로 만들기 때문에 WASM은 매번 초기화될 수 있다. 대신 일시적으로 커진 메모리를 다음 파일까지 계속 쥐고 있지 않는다.
2. 범용 파서로 글꼴을 새로 생성하면 커닝·변형·희귀 테이블이 바뀔 수 있다. 기존 테이블을 포장/해제하고 Google 참조 구현 기반 WASM을 WOFF2에 사용하는 쪽으로 결정했다. 다른 곡선 타입으로 바꾸는 옵션은 지원한다고 표시하지 않는다.
3. 미완료 Codec을 백분율로 가장하지 않았다. 테이블 처리처럼 비율을 알 수 있는 구간만 숫자를 사용하며, 압축 중에는 단계 이름과 무한 진행 표시를 함께 보여준다.
4. 모바일 메모리 정보가 누락되는 경우 상향 가정하지 않고 기본 한도를 낮췄다. 취소 뒤 이전 작업의 예정 콜백이 신규 작업을 덮는 경쟁을 세대 번호로 차단한다.
5. 처리 라이브러리를 초기 UI 엔트리에서 분리했다. 기준 빌드에서는 앱 JS 약 7.5 kB, 초기 공유 포맷 모듈 약 0.9 kB, CSS 약 6.1 kB(압축 전). 작업자 엔진은 파일을 변환할 때만 시작하고, WOFF2 디코더와 인코더는 필요한 작업에서만 동적 로딩된다. 약 295 kB 디코더와 약 1.02 MB 인코더의 수치는 빌드 산출물 원본 크기이며 네트워크 압축 후 수치가 아니다.

6. 첫 Chromium 실험에서 엔진의 Emscripten 바인딩이 동적 함수 생성을 사용한다는 사실을 확인했다. 본문 HTML은 `script-src 'self'`를 유지하고 별도의 작업자 응답 하나에만 필요한 예외를 두었다. 작업자의 연결은 같은 출처로 제한하고, 문서에 임의 URL의 코드나 HTML을 삽입하는 기능은 없다. 향후 동적 실행을 끈 레퍼런스 엔진으로 대체할 수 있다.

## 검증 방법

- `npm run typecheck`, `npm test`, `npm run build`.
- 실제 Noto Sans TTF, Latin Modern CFF OTF를 WOFF1/2로 왕복: SFNT 유형과 복원 테이블의 일치 확인. 실폰트 환경변수를 제공하지 않으면 해당 케이스만 건너뛴다.
- 브라우저 검증은 UI 초기 상태에서 별도의 WOFF2 청크를 미리 요청하지 않는지, 변환 후 내려받은 파일의 매직 바이트, 작업자 중지 후 재시작, 화면의 가로 스크롤과 네트워크 요청을 본다. 노드와 Chromium 결과는 Safari·Firefox·저사양 실물 기기에 대한 전수검증이 아니다.

## Cloudflare

Pages의 GitHub 저장소는 이 저장소 하나에 연결한다. Production branch `main`, build command `npm run build`, output `dist`, Preview 자동 배포는 끈다. 개발 서버를 띄우는 명령이나 Pages Functions는 없다. 운영 주소는 `switcher.rhee.life`다. GitHub Actions 자체의 활성/비활성 여부와 Cloudflare 네이티브 배포는 별개로 확인해야 한다.
