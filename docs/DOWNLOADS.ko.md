# 다운로드·쿠키·운영 문서 개발기

## 브라우저 기본이 우선

변환 결과는 기본으로 선택된다. 선택 파일 받기를 누르면 같은 클릭에서 각 Blob 다운로드를 요청한다. ZIP으로 묶거나 서버에 보내지 않는다. 브라우저는 첫 파일만 허용하거나 복수 파일 정책·다운로드 위치를 확인할 수 있다. 이 제한을 우회하지 않으며 앱에서는 요청 건수만 표시한다. 완료나 디스크 기록을 브라우저 대신 단정하지 않는다.

## 폴더 선택이 가능한 브라우저

브라우저 기본 다운로드 체크를 끄면 폴더 선택을 사용할 수 있다. 지원하지 않는 환경에서는 기본 다운로드만 표시한다. 변환 전이나 결과가 나온 다음 골라도 된다. 폴더가 아직 없을 때 ‘폴더에 저장’을 누르는 것 역시 사용자 직접 동작으로 폴더 요청을 연다. 브라우저가 취소·거절하면 기본 모드로 조용히 바꾸지 않는다.

폴더 저장은 원래 결과 Blob을 사용한다. 한 번에 최대 두 건을 저장하며, 이미 존재하는 이름과 겹치면 뒤에 `-2` 같은 접미사를 붙인다. 앱 내부 병렬 쓰기에서 예약 이름을 공유하고 가능한 브라우저에서는 배타적 쓰기 모드를 요청한다. 다른 프로세스가 동시에 만든 파일과의 경쟁을 완전히 막는 OS 수준의 원자적 생성 보장은 아니다. 쓰기 실패 시 스트림 중단을 시도하고 코드만 오류 기록에 남긴다.

## 저장하지 않는 것

다운로드 모드를 선택할 때만 90일 기한의 설정 쿠키를 쓴다. 이름은 `jjondeukCookie`, 값은 `smoreCookie`(브라우저) 또는 `gingerbreadManCookie`(폴더)와, `christmasCookie`(자동 선택) 또는 `purePickledGingerCookie`(수동 선택)를 조합한 버전 있는 고정 문자열이다. 두 가지 설정만 저장한다. 파일명, 경로, 실제 권한, 폴더 핸들 및 오류 로그는 쿠키에 넣지 않는다.

## 운영 경계

개인정보처리방침과 이용약관은 스크립트 없이 열리는 정적 페이지다. 변환기가 온라인이라는 것은 HTML·CSS·JS를 Cloudflare가 전달한다는 뜻이지, 폰트 처리 서버가 있다는 뜻이 아니다. 호스팅 제공자에 필요한 접속 정보 처리 가능성과 변환 데이터가 전송되지 않는다는 사실을 구분해 설명한다. 운영 권한 변경과 보안 판단은 [거버넌스](../GOVERNANCE.md)와 [보안 정책](../SECURITY.md)을 따른다. GitHub Actions는 계속 비활성화 상태를 유지한다.

[Chrome의 File System Access 공식 문서](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access) · [Cloudflare 개인정보 정책](https://www.cloudflare.com/privacypolicy/)

## 검증

실제 Chromium의 390px·1280px 환경에서 변환·복원·다운로드·취소를 확인했다. 앱이 같은 클릭으로 ZIP 없는 두 건을 요청하는지, 폴더를 전후에 고를 수 있는지, 기존 이름을 건너뛰는지, 쿠키만 남고 폴더 핸들은 새로고침 후 사라지는지는 제어된 브라우저 파일 시스템 대역으로 검증했다. 파일 시스템 대역 시험은 OS별 실제 폴더 선택창의 검증을 뜻하지 않는다. 단위 시험과 타입 검사, 정적 빌드도 수행했다.
